## 🎯 为什么做这套系统

贷款中介公司的日常，往往被这些问题拖垮：

| 痛点 | 助贷 CRM 的解法 |
| :--- | :--- |
| 📋 客户资料躺在 Excel 和微信里，业务员撞单、离职带走客户 | **线索池 → 客户公海 → 跟进留痕**，全程系统化沉淀，谁跟进、跟进到哪一步一目了然 |
| 🧮 佣金靠嘴算、月底对不上账，团队为分钱扯皮 | **先定佣金池、再按贡献比例分配**，池子与比例全程快照留痕，规则透明 |
| 📉 放款了多少、实收了多少、净赚了多少，一笔糊涂账 | **实收 / 成本 / 净业绩 / 佣金四账分立**，与贷款本金完全解耦，财务口径清晰 |
| ✏️ 历史业绩改了就查不到，出了纠纷说不清 | **业绩版本链**：确认后纠错不覆盖历史，每一版谁改的、为什么改，全部留痕 |
| 📞 通话执行过程与跟进记录分散，主管难以核对 | **安卓协同拨号 + 独立通话记录**：已实现任务、状态与录音查询机制；真实外呼与系统录音兼容仍需目标机型验收 |
| 💸 买线索花的钱难以归属到人与渠道 | **数据成本核算**：按首次分配保存归属与单价快照，独立汇总获客投入，不扣个人分佣或改写业务净业绩 |
| 🏢 多门店 / 多团队各管一摊，老板看不到全局 | **企业内部门数据权限 + 全企业报表**；多公司按独立租户管理，平台运营侧负责租户生命周期 |

> 系统内置的进件模型面向助贷场景：业务员在线下帮客户完成放款后，录入放款事实与凭据并提交渠道核实，再由有核算确认权限的人员确认实收、成本和分佣。这里的“进件”是放款后的业绩上报，不是银行贷前审批。

### ① 登录与经营工作台

当前登录采用滑动拼图验证；连续密码错误 5 次锁定 15 分钟，多端会话由 Redis 管控。下图保留的是旧字母验证码界面，尚未补拍，不代表当前登录交互。

![登录](screenshots/01-登录.png)

「先处理待办，再看实收与分佣」——待跟进任务 / 待核实上报 / 已分配待首访 / 新客池入口直达业务；按核算日期汇总实收、直接成本、净业绩与佣金池，明细可按人员、部门或全企业维度查看，具体范围由权限决定。当前经营工作台未提供经营报表 Excel 导出。

线索／客户工作台支持按筛选条件创建**异步 CSV 导出任务**，手机号脱敏；任务持久化、下载权限核验与访问审计已实现。中断且仍为待处理状态的任务可在租约过期后重新生成整件文件，最多认领 3 次；已标记失败或认领次数耗尽时须重新创建任务，不提供文件断点续传。单任务最多 100,000 行，结果保留 7 天。

### ④ 通话记录 —— 安卓协同拨号与执行记录

### ⑥ 放款上报（进件）—— 记录放款事实，按业务标识防重

业务员录入线下放款事实，渠道部门核实；通过请求幂等、版本控制与唯一约束降低重复申报风险，同一租户、同一机构的相同放款流水号受唯一约束保护。不同流水号是否对应同一现实放款仍需业务核实；同一客户同一产品的进行中申请另受约束。核实不通过可**退回补正**，业务员补齐事实后重新提交，状态流转留痕。

![放款上报列表](screenshots/19-放款上报.png)

上报工作区：选客户 → 根据已录资质筛选产品方案 → 填报放款事实与机构流水 → 附加放款凭据并提交核实。产品匹配依赖维护的准入参数和客户资料，不等同于银行审批或放款保证。

![上报放款](screenshots/20-上报放款.png)

### ⑦ 业绩核算 —— 财务口径的净业绩，不是流水账

实收服务费、渠道返佣、逐笔直接成本分账登记，自动得出**净业绩**；房租底薪等期间费用不摊入单笔业务，口径干净。每笔已核实进件对应一张业绩单，版本与状态一目了然。

![业绩核算](screenshots/23-业绩核算.png)

佣金池工作台（已确认）：**第一步定实收与直接成本 → 第二步定佣金池 → 第三步按贡献比例分配**。参与人、部门、比例和金额保存确认时快照；确认后纠错生成新版本，旧版保留更正记录，不以当前人员关系覆盖历史。

![业绩详情-佣金池分配-已确认](screenshots/24-业绩详情-佣金池分配-已确认.png)

新核实的进件进入「待确认」向导：有核算确认权限的人员逐笔录入实收、成本与凭据说明，确认佣金池及参与人贡献比例后生成分佣。核算操作由后端权限控制，具体授权角色由企业配置。

![业绩详情-待确认向导](screenshots/25-业绩详情-待确认向导.png)

按人查看佣金明细，关联核算版本与进件单据；更正核算时撤销原版分佣并保留历史。有效分佣表示已确认的分配结果，不表示佣金已支付。

![佣金管理](screenshots/26-佣金管理.png)

### ⑧ 数据成本 —— 买线索花的钱，摊到人和渠道

按**首次分配归属**核算各渠道线索的数据成本：首次归属、部门、日期和单价保存快照，单价 × 数量汇总到员工与渠道；未定价数据单独标记，管理员可补计。回收、转派与再次领取不转移或重复计费，改价只影响后续首配；数据成本独立统计，不扣佣金池或个人分佣，也不改写业务净业绩。

### ⑩ 平台运营 —— 独立入口管理租户生命周期

独立的平台运营后台使用独立认证与会话，管理租户开通、续期与启停。统一部署采用共享数据库，业务表以 tenant_id、组合约束和后端查询／授权条件划分租户，企业内再按角色与部门控制范围；这不等同于每家公司独立数据库或数据库自动实施查询隔离。独立安装与 SaaS 运营方案可按交付需求洽谈，跨租户隔离须在目标环境验收。下图只有一个开发租户，不是多公司隔离测试结果。

## 💼 适用场景与合作方式

- **贷款中介 / 助贷公司**：单团队或总部 + 多门店，部署前核对业务口径、角色配置与环境
- **渠道联盟 / 居间团队**：多公司按租户组织数据，独立团队权限与共享运营方案须按具体场景验收
- **定制交付**：业务口径、佣金规则、报表口径可按需定制

支持**私有化部署 / 定制开发**，可预约在线演示。交付内容、部署责任、培训、维护和源码授权范围另行洽谈；产品源码保持私有，不在本展示仓库公开。试点和正式交付应分别确认功能清单、运行环境与验收结果。
